# 本地 AI（Ollama）插件

调用本机 Ollama 跑一个本地大模型。**测试 / 演示用**，主要展示「怎么把一个本地服务接进插件架构」。

## 前置条件

1. 装好 Ollama 并让它在跑（默认 http://127.0.0.1:11434）。
2. 至少拉了一个模型，例如：
   ollama pull qwen3:0.6b
3. **设置页的「输出编码」要是 UTF-8**。脚本内部已强制自己按 UTF-8 输出，但如果宿主 shell 是 Windows PowerShell 5.1 且编码设成 GBK，中文仍可能乱码。（装了 PowerShell 7 的话程序默认就是 UTF-8，一般不用管。）

不满足会怎样：连不上 Ollama、或模型不存在时，插件会打印清楚的提示（还会把已装的模型列出来），不会静默失败。

## 参数

| # | manifest name | run.ps1 参数 | 说明 |
|---|---|---|---|
| 1 | prompt | $Prompt | 要问的内容，必填 |
| 2 | style | $Style | 简洁 / 详细 / 代码，决定温度和最大长度 |
| 3 | model | $Model | 模型名，留空默认 qwen3:0.6b；支持前缀匹配（填 qwen3 能命中 qwen3:0.6b） |

顺序是契约，改一个必须同步改另一个。model 放最后是有意的：宿主对空的中间参数会直接跳过导致后面整体错位，只有末尾的空参数省略才安全。

## 输出示例

    [ollama] 模型=qwen3:0.6b  风格=简洁 (temperature=0.3)
    --------------------------------------------------------
    Java的垃圾回收机制通过垃圾收集器管理内存分配……
    --------------------------------------------------------
    [ollama] 生成 371 tokens，用时 29.9s，约 12.4 tokens/秒

最后一行的实测吞吐是脚本从 Ollama 返回的计时算出来的，可以直接抄进研究报告当性能数据。

## 老实说一句：别拿它写代码

这个 0.6B 模型闲聊、问答还行，但代码能力是坏的。实测让它写「判断回文字符串」，它给的是：

    String reversed = new String(s);   // 只是复制，没反转
    return reversed.equals(s);          // 永远返回 true

—— 一个对所有输入都返回 true 的错误函数。所以本插件适合演示「能扩展出本地 AI 功能」这件事，不适合真拿来生成代码。选「代码」风格也只是让它多吐点字，不代表吐得对。

## 为什么需要 run.ps1 这层包装

宿主机拼命令行的方式是 executable + 按表单顺序的值，没法在某个值前面插 flag，也没法表达「POST 一段 JSON 到 HTTP 接口」这种逻辑。所以把调 API、组请求体、解析响应、控制编码全收进 run.ps1，manifest 里只声明用户要填的值。
